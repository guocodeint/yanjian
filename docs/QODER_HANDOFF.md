## 已确认的最终方向

产品“研笺·文献助手”，面向药学学生。主流程：注册登录 → 提出问题 → Europe PMC 检索 → 文献筛选 → 证据矩阵 → 可追溯简报 → 账号保存和文件导出。

**最新决策覆盖早期规划：采用账号登录、服务端数据库、私有文件存储和跨设备恢复。不要再实现 IndexedDB 单机历史或匿名会话。**用户愿意升级 Qoder Pro 以支持动态应用，具体套餐能力以账号实际可用状态核验。

本目录提供本地参考实现。请在独立目录重建，保存真实开发与部署过程。具体功能与验收以根目录《给Qoder的Prompt.md》为准。

## 可直接发送给 Qoder 的首条任务

> 请依据本目录的 README、shared/schema.ts 和 docs/API.md，重新实现“研笺·文献助手”参赛工程。首先读取接口、页面和验收说明，在独立项目目录工作。保留注册登录、账号隔离、真实 Europe PMC 题录/摘要检索、DeepSeek 服务端调用、可编辑证据表、带来源的简报、账号历史及文件导出。前端采用 React + TypeScript，风格参考截图：浅色、青绿色强调、清晰的研究工作台。部署目标是 Qoder Sites 动态应用，使用托管数据库和私有对象存储。先验证当前套餐是否支持所需数据库、服务端函数、私有存储、Cookie 会话、外部 API 和 AI 调用时长，再创建最小贯通部署。不要把 SQLite 或服务器本地目录当作 Sites 的持久化存储。不要将 API 密钥写进前端。不要声称读过全文，不生成缺乏来源的研究结论。分阶段交付，每阶段用浏览器验收，再继续下一阶段。

## 分阶段任务

1. **平台验证与账号（第 1—2 天 / 重建第 1 天优先）**：核验 Pro 权益，建立 Sites 测试项目，完成数据库迁移、私有对象写读、服务端外部请求、会话 Cookie 验证。实现注册、登录、退出、7 天会话和账号隔离。平台支持可靠托管身份时可替换本地 scrypt 适配器，但保持前端账号体验及验收行为。
2. **检索和证据（参考第 3—6 天 / 重建第 2 天）**：实现真实检索与分页、10 篇上限、手工整理、AI 提取和引用校验。单次长 AI 请求超过平台函数时长时改为持久化任务提交和轮询，失败保持数据并提供手动重试，不无限重试付费请求。
3. **保存和导出（参考第 7 天交接 / 重建第 3 天）**：研究 JSON 写入托管数据库；CSV、Markdown、JSON 以不可变快照写入私有对象存储。下载需服务端验证所有权后代理或生成短时签名 URL。保留参考版的数据库修订号实现乐观锁，两个设备并发编辑冲突必须提示，不静默覆盖。
4. **部署与验收（第 11—12 天）**：个人设置、账号级加密密钥与模型、HTTPS、安全 Cookie、共享限流、每账号和全站 AI 预算、日志脱敏；实际公开地址注册新账号，完成非预置主题检索和真实分析，验证异地设备恢复。
5. **材料与缓冲（第 13—14 天）**：补齐真实提示词截图、修订过程、公开链接、五步使用说明和作品介绍。不得虚构开发截图或用户测试反馈。

## 数据库和存储映射

| 实体 | 关键字段 | 权限与约束 |
|---|---|---|
| users | id、username、password_hash、created_at | 用户名规范化唯一；密码只存哈希，或改用托管身份 |
| sessions | token_hash、user_id、expires_at | Cookie 令牌随机，数据库不存明文；退出撤销 |
| projects | id、user_id、payload、updated_at、revision | 所有查询强制 owner 范围；并发更新检查 revision |
| exports | id、user_id、project_id、filename、object_key、mime、created_at | 元数据与私有对象对应；下载和删除按 owner 校验 |

本地 `data/research.sqlite3` 和 `data/objects` 只用于参考流程验证。Qoder 重新创建云表和存储桶，不上传这些目录。正式版数据备份须包含数据库和对象，定期执行恢复演练。

## 页面与交互

- 登录页：用户名密码、注册切换、明确错误。首版无找回密码；如比赛阶段需要，应先设计身份验证再实现，不能提供无验证重置。
- 开始研究：使用说明、空白问题和英文检索式、年份范围。AI 检索词建议需用户确认。
- 文献工作台：题录、摘要、来源、年份、每批最多 60 篇，去重并统一排序、最多 10 篇、人工纳入/排除与备注。
- 证据矩阵：对象、方法、发现、局限、原句。保留 AI 原始版本和人工修订。
- 研究简报：可编辑、出处可追溯、研究范围变更提示。打印布局需完整显示长段落。
- 账号研究库：跨设备恢复、项目删除、JSON 导入副本、导出文件列表。公开链接只公开应用，不公开用户资料。

## 必须保留的失败行为

没有密钥仍能检索和手工整理；同时缺少可读全文和摘要时不自动提取；空结果与网络错误不同；AI 超时、鉴权失败、余额不足、配额用尽、错误引用均有明确提示。失败不得清除研究记录，不以示例或模板假装在线成功。

不实现模型训练、性质预测、PDF 上传解析、全文问答、向量库、团队协作。

## 提交前验收

- 两个账号互不可读写对方研究和文件，包括猜测项目 ID 和下载 URL。
- 同一账号在全新浏览器登录可恢复项目与导出文件；退出后旧令牌不可用。
- 一个非预置问题跑通真实在线检索与 AI；人工核对至少三篇原句和对应结论。
- 无密钥、无摘要、空结果、超时、余额不足、伪造引用和超额请求可控失败。
- 桌面和 390px 手机完成主流程；打印 PDF 长段落不被裁切。
- 保存失败或并发冲突不能显示“已同步”；恢复入口明确。
- 源码包、静态构建、网络响应、日志和导出中不存在密钥与密码哈希。
- 实际公开 URL 验证后才标记发布完成。当前参考工程测试不替代 Sites 部署测试。
